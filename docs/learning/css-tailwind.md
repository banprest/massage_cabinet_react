## 0. Главная мысль

Tailwind — это **не замена CSS, а способ его писать**. Каждый класс Tailwind — это одна-две строки обычного CSS:

| Tailwind | Обычный CSS |
|---|---|
| `p-4` | `padding: 1rem;` |
| `flex` | `display: flex;` |
| `text-emerald-900` | `color: <тёмно-зелёный>;` |

Поэтому если вёрстка «не слушается», проблема почти всегда в **понимании CSS** (блочная модель, flex, ширина родителя), а не в Tailwind. Сначала разделы 1–5 про CSS, потом Tailwind.

> Rails-аналогия: Tailwind относится к CSS как ActiveRecord к SQL. Писать удобнее, но когда что-то идёт не так, нужно понимать, что происходит внизу.

## 1. Как браузер решает, какой стиль применить

### Правило CSS

```css
.card {              /* селектор: к каким элементам */
  padding: 16px;     /* свойство: значение */
  color: #333;
}
```

### Каскад и специфичность

Если к элементу подходят **несколько правил** с одним свойством, побеждает:
1. более **специфичный** селектор: `#id` > `.class` > `tag`;
2. при равной специфичности — правило, которое **ниже** в файле (позже подключено).

Это главный источник боли в обычном CSS: «почему мой стиль не применился?» Потому что где-то есть селектор специфичнее. В Tailwind почти все классы одной специфичности (один класс), поэтому таких войн почти нет. Это одна из причин, почему мы его выбрали.

### Наследование

Некоторые свойства **передаются детям**: всё, что про текст (`color`, `font-size`, `font-family`, `line-height`). Поставил `text-stone-700` на `<main>`, и весь текст внутри серый.

Свойства «коробки» **не наследуются**: `padding`, `margin`, `border`, `background`, `width`.

### Единицы измерения

| Единица | Что значит | Когда использовать |
|---|---|---|
| `px` | пиксели | рамки (`1px`), мелкие точные вещи |
| `rem` | размер шрифта корня (обычно 16px) | **шрифты и отступы**: уважают настройку «крупный шрифт» у пользователя |
| `%` | процент от **родителя** | ширина относительно контейнера |
| `vh` / `dvh` | процент высоты окна | «на весь экран»; на телефоне лучше `dvh` (см. §11) |
| `fr` | доля свободного места в Grid | колонки сетки |

В Tailwind об этом думать почти не надо: шкала уже в `rem`.

## 2. Блочная модель: каждый элемент — коробка

Это **самое важное** в CSS. Любой элемент — прямоугольник из четырёх слоёв:

```
┌──────────────── margin (внешний отступ, прозрачный) ────────────────┐
│ ┌────────────── border (рамка) ───────────────────────────────────┐ │
│ │ ┌──────────── padding (внутренний отступ, с фоном) ───────────┐ │ │
│ │ │                                                             │ │ │
│ │ │                 content (текст, картинка)                   │ │ │
│ │ │                                                             │ │ │
│ │ └─────────────────────────────────────────────────────────────┘ │ │
│ └─────────────────────────────────────────────────────────────────┘ │
└─────────────────────────────────────────────────────────────────────┘
```

- **padding** — расстояние от содержимого до рамки. Фон элемента его закрашивает. Кнопке нужен padding, чтобы текст не лип к краям.
- **margin** — расстояние **между** элементами. Прозрачный.
- **Правило:** отступ **внутри** коробки — padding, отступ **между** коробками — margin, а ещё лучше `gap` у родителя (§3).

**`box-sizing: border-box`.** По умолчанию в CSS `width: 200px` задаёт ширину только содержимого, а padding и border **добавляются сверху**. Элемент получается шире, чем ты написал. Tailwind сразу включает для всех элементов `border-box`: ширина включает padding и border. Так считать проще.

### `display`: как коробка ведёт себя в потоке

| Значение | Поведение | Примеры тегов по умолчанию |
|---|---|---|
| `block` | занимает **всю ширину**, следующий элемент с новой строки | `div`, `p`, `h1`, `section` |
| `inline` | течёт **внутри текста**, ширину и вертикальные отступы игнорирует | `span`, `a`, `b` |
| `inline-block` | в строке, но ширина и отступы работают | кнопки |
| `flex` / `grid` | коробка становится **контейнером раскладки** для детей (§3) | — |
| `none` | элемента нет вообще | — |

Частая загадка «почему `mt-4` не работает на `<span>`» — потому что `inline` игнорирует вертикальные отступы.

### 🔍 Как смотреть

Firefox → F12 → **Инспектор** → выбери элемент → справа вкладка **«Разметка»** (Layout). Там нарисована эта самая коробка с реальными числами margin/border/padding. Наведи на элемент в дереве, и на странице подсветятся слои: margin жёлтым, padding фиолетовым. **Это главный инструмент отладки вёрстки.**

## 3. Раскладка: как расставить коробки

Три режима, от простого к мощному.

### 3.1. Обычный поток (normal flow)

Без всяких настроек block-элементы идут **сверху вниз** на всю ширину, inline — слева направо внутри строки. Для текста (статья, описание) этого хватает.

### 3.2. Flexbox — раскладка в **одну линию**

Ставишь родителю `display: flex` (Tailwind: `flex`), и его **прямые дети** выстраиваются в линию.

Две оси:

```
           главная ось (main axis) →  flex-row (по умолчанию)
         ┌───────────────────────────────────────────┐
  попе-  │  [ребёнок 1]  [ребёнок 2]  [ребёнок 3]     │
  речная │                                           │
  ось ↓  └───────────────────────────────────────────┘
```

| Что | Свойство CSS | Tailwind | Вдоль какой оси |
|---|---|---|---|
| направление | `flex-direction` | `flex-row` / `flex-col` | задаёт главную ось |
| распределение | `justify-content` | `justify-start` / `-center` / `-between` / `-end` | **главная** |
| выравнивание | `align-items` | `items-start` / `-center` / `-end` / `-stretch` | **поперечная** |
| расстояние между детьми | `gap` | `gap-2`, `gap-4` | обе |
| перенос на новую строку | `flex-wrap` | `flex-wrap` | — |
| «займи всё свободное место» | `flex: 1` | `flex-1` (на ребёнке) | — |
| «не сжимайся» | `flex-shrink: 0` | `shrink-0` (на ребёнке) | — |

**Ловушка:** при `flex-col` оси меняются местами. Теперь `justify-*` двигает по **вертикали**, а `items-*` по **горизонтали**. Если центрирование «не работает», проверь направление.

Типичные приёмы:
```tsx
{/* шапка: логотип слева, меню справа */}
<header className="flex items-center justify-between">

{/* иконка + текст в кнопке */}
<button className="flex items-center gap-2">

{/* всё по центру экрана */}
<main className="flex min-h-dvh flex-col items-center justify-center">
```

### 3.3. Grid — раскладка в **две оси** (строки и колонки)

Родителю `display: grid` (`grid`) плюс описание колонок.

```tsx
{/* ровно 3 колонки */}
<div className="grid grid-cols-3 gap-4">

{/* на телефоне 1 колонка, на планшете 2, на ПК 3 */}
<div className="grid grid-cols-1 gap-4 md:grid-cols-2 lg:grid-cols-3">

{/* ребёнок занимает 2 колонки */}
<div className="col-span-2">
```

Помнишь сетку карточек в песочнице? `grid-template-columns: repeat(auto-fill, minmax(220px, 1fr))` — «столько колонок шириной от 220px, сколько влезет». В Tailwind это записывается произвольным значением: `grid-cols-[repeat(auto-fill,minmax(220px,1fr))]`. Но адаптивный вариант через `md:` / `lg:` читается проще.

### Flex или Grid?

| Задача | Выбор |
|---|---|
| элементы в ряд или столбик: меню, кнопки, иконка+текст, шапка | **Flex** |
| сетка карточек, каркас страницы (боковая панель + контент), форма с выровненными колонками | **Grid** |
| сомневаешься | начни с Flex; если придётся выравнивать и строки, и колонки сразу — Grid |

📖 [MDN: основные понятия Flexbox (рус.)](https://developer.mozilla.org/ru-RU/docs/Web/CSS/CSS_Flexible_Box_Layout/Basic_Concepts_of_Flexbox) · [Гид по CSS Grid (рус.)](https://thecode.media/gid-po-css-grid/) · [web.dev: Grid (англ., очень наглядно)](https://web.dev/learn/css/grid)

### 🔍 Как смотреть

В Инспекторе Firefox рядом с элементом, у которого `display: flex` или `grid`, стоит значок **flex** / **grid**. Нажми на него, и на странице нарисуются линии раскладки: оси, колонки, промежутки. Инструменты Firefox для Flex/Grid — лучшие среди браузеров, пользуйся.

## 4. Позиционирование (знать, но использовать редко)

| Tailwind | Что делает | Пример применения |
|---|---|---|
| `relative` | элемент на своём месте, но становится **точкой отсчёта** для `absolute`-детей | обёртка карточки со значком |
| `absolute` | вынут из потока, ставится по `top/left/...` относительно ближайшего `relative`-родителя | значок «Хит» в углу карточки |
| `fixed` | прибит к окну, не скроллится | всплывающее уведомление |
| `sticky` | едет со страницей, но «прилипает» у края | шапка таблицы, шапка сайта |

Значок в углу:
```tsx
<article className="relative">
  <span className="absolute top-2 right-2">Хит</span>
</article>
```

`z-index` (`z-10`, `z-50`) — кто кого перекрывает. **Работает только у позиционированных элементов** (`relative`/`absolute`/`fixed`/`sticky`) и у детей flex/grid.

**Правило:** если тянет сделать раскладку через `absolute` — почти всегда правильнее Flex или Grid. Absolute — для «наклеек» поверх, а не для расстановки блоков.

## 5. Адаптивность: один сайт для телефона и компьютера

Половина клиентов массажиста откроет сайт **с телефона** из мессенджера. Адаптивность у нас не опция.

### Mobile-first

В Tailwind класс **без префикса работает на всех экранах**, а префикс `md:` добавляет изменение **начиная с** этой ширины:

```tsx
<h1 className="text-3xl md:text-5xl">
//              ↑ везде      ↑ от 768px и шире
```

Отсюда порядок работы: **сначала верстай для узкого экрана, потом добавляй префиксами то, что меняется на широком.** Не наоборот.

| Префикс | С какой ширины | Примерно |
|---|---|---|
| (нет) | 0 | телефон |
| `sm:` | 640px | большой телефон горизонтально |
| `md:` | 768px | планшет |
| `lg:` | 1024px | ноутбук |
| `xl:` | 1280px | компьютер |

### Правила
- **Не задавай фиксированную ширину** блокам с содержимым (`w-[800px]`). Задавай **максимальную**: `max-w-3xl` + `mx-auto` (центрирование) + `px-4` (поля по бокам). Это стандартный контейнер страницы.
- Картинкам: `max-w-full h-auto` или `w-full object-cover`, иначе вылезут за экран.
- Метатег `<meta name="viewport" ...>` в `index.html` уже есть от Vite. Без него телефон отрисует «десктоп» и уменьшит его.

### 🔍 Как смотреть
Firefox → **Ctrl+Shift+M** (режим адаптивного дизайна). Выбираешь модель телефона или тянешь за край. Проверяй каждую страницу на ширине **375px** (типичный телефон).

## 6. Tailwind: как он устроен

### Шкала значений

Отступы и размеры: **1 единица = 0.25rem = 4px**.

| Класс | Значение |
|---|---|
| `p-1` | 4px |
| `p-2` | 8px |
| `p-4` | 16px |
| `p-6` | 24px |
| `p-8` | 32px |

Направления: `p` (все стороны), `px` (лево+право), `py` (верх+низ), `pt`/`pr`/`pb`/`pl` (одна сторона). То же для `m` (margin). `mx-auto` — центрировать блок по горизонтали.

Цвета: `<палитра>-<оттенок>`, оттенки от `50` (почти белый) до `950` (почти чёрный). `bg-emerald-100`, `text-stone-600`, `border-stone-300`.

### Состояния — префиксы

| Префикс | Когда применяется |
|---|---|
| `hover:` | наведение мышью |
| `focus-visible:` | фокус с клавиатуры (Tab) |
| `active:` | в момент нажатия |
| `disabled:` | у отключённого элемента |
| `md:`, `lg:` … | ширина экрана (§5) |
| `dark:` | у пользователя тёмная тема ОС |

Комбинируются: `md:hover:bg-emerald-700`.

```tsx
<button className="rounded-lg bg-emerald-700 px-4 py-2 text-white hover:bg-emerald-800 focus-visible:outline-2 focus-visible:outline-offset-2 disabled:opacity-50">
  Записаться
</button>
```

### Как Tailwind находит классы — ⚠️ важная ловушка

Tailwind **не выполняет** твой код. При сборке он **читает исходники как текст** и ищет строки, похожие на его классы. Найденные попадают в CSS, остальные нет.

Отсюда правило: **класс должен быть написан в коде целиком.**

```tsx
// ❌ НЕ РАБОТАЕТ: строки "bg-emerald-500" в коде нет, Tailwind её не найдёт
<div className={`bg-${color}-500`} />

// ✅ РАБОТАЕТ: полные имена классов есть в коде
const colors = {
  success: "bg-emerald-500",
  danger: "bg-red-500",
};
<div className={colors[status]} />
```

Это самая частая ошибка новичков в Tailwind: «класс есть в DevTools, а стиля нет».

### Условные классы

Как в песочнице, тернарником:
```tsx
<article className={isSelected ? "border-2 border-emerald-700" : "border border-stone-300"}>
```

Когда условий много, используют маленькую функцию `cn(...)`. Её добавит shadcn/ui, когда мы его поставим:
```tsx
<article className={cn("rounded-lg p-4", isSelected && "border-emerald-700 bg-emerald-50")}>
```
`cn` склеивает строки, выкидывает `false`, а при конфликте (`p-4` и `p-2`) оставляет последний.

### Свои цвета и шрифты: `@theme`

В Tailwind 4 своя палитра задаётся прямо в CSS:
```css
@import "tailwindcss";

@theme {
  --color-brand-50: #f0f7f3;
  --color-brand-700: #2f6b4f;
}
```
После этого работают `bg-brand-700`, `text-brand-50`. Так мы и оформим айдентику «Возрождения» (раздел 10 `CLAUDE.md`). Тогда во всём проекте будет `bg-brand-700`, а не россыпь `emerald-700`, `green-800`, `#2f6b4f`. Это и есть дизайн-токены.

### Произвольные значения: `[...]`

`w-[37px]`, `bg-[#2f6b4f]`, `top-[13px]` — запасной выход, когда в шкале нет нужного. **Используй редко.** Если пишешь `[…]` часто, значит, ты вышел из системы, и интерфейс снова станет разнобойным. Нужный цвет добавь в `@theme`, а отступ округли до шкалы.

### Повторяющиеся классы

Если одна и та же длинная строка классов встречается в пяти местах — это сигнал **сделать компонент**, а не CSS-класс:
```tsx
export function Button({ children }: { children: ReactNode }) {
  return <button className="rounded-lg bg-brand-700 px-4 py-2 text-white ...">{children}</button>;
}
```
В Tailwind есть `@apply` (собрать утилиты в CSS-класс), но документация сама советует не злоупотреблять им. В React компонент и есть способ переиспользования.

### Preflight: сброс стилей

`@import "tailwindcss"` подключает **Preflight**, сброс стилей браузера. Поэтому `<h1>` выглядит как обычный текст, у списков нет точек, а у кнопок нет рамки. Это не баг: все стили задаёшь явно. Нужны точки у списка — `list-disc pl-5`.

В Tailwind 4 `border` по умолчанию рисует рамку **цветом текста** (`currentColor`). Всегда указывай цвет: `border border-stone-300`.

## 7. Альтернативы Tailwind и почему мы выбрали его

| Подход | Как выглядит | Плюсы | Почему не для нас |
|---|---|---|---|
| **Обычный CSS / BEM** | `.service-card__title` в `.css` | никаких зависимостей, стандарт | имена, войны специфичности, мёртвый CSS копится; на большом проекте тяжело |
| **CSS Modules** | `styles.card` из `Card.module.css` | стили изолированы в компоненте, Vite поддерживает из коробки | хороший вариант! Но всё равно придумывать имена и прыгать между файлами; нет готовой шкалы; shadcn/ui на Tailwind |
| **Sass / SCSS** | переменные, вложенность | был стандартом 10 лет | большую часть уже умеет обычный CSS (переменные, вложенность); ещё одна зависимость |
| **CSS-in-JS** (styled-components, Emotion) | стили в JS: `` styled.div`...` `` | динамика, изоляция | стили вычисляются **в браузере во время работы**, это медленнее; плохо дружит с новыми возможностями React; styled-components в 2025 ушёл в режим поддержки. Индустрия от этого уходит |
| **Готовые библиотеки компонентов** (Bootstrap, MUI, Ant Design) | `<Button variant="primary">` | быстро получить «прилично» | все сайты выглядят одинаково; кастомизировать дизайн под «Возрождение» — борьба с библиотекой; тяжёлые |
| **UnoCSS** | как Tailwind | ещё быстрее и гибче | меньше экосистема и документации; shadcn/ui рассчитан на Tailwind |
| **Tailwind** ✅ | классы в разметке | шкала, нет войн специфичности, маленький итоговый CSS, огромная экосистема, shadcn/ui | длинные `className`, нужно выучить словарь классов (IntelliSense очень помогает), разметка «шумнее» |

Честно о минусах Tailwind: первые дни классы кажутся мусором в разметке. Это проходит, когда начинаешь читать их как обычный CSS. А IntelliSense при наведении показывает, что стоит за каждым классом.

### shadcn/ui — что это (будет в следующих задачах)

Это **не библиотека в `node_modules`**, а набор готовых компонентов (кнопка, диалог, выпадающий список, календарь), которые **копируются исходным кодом в твой проект** командой `npx shadcn add button`. Внутри Tailwind и библиотека Radix, которая отвечает за поведение и доступность: фокус, клавиатура, скринридеры.

Плюс: код твой, меняешь как угодно, нет борьбы с чужой библиотекой. Диалог или календарь с правильной доступностью руками писать долго и сложно, поэтому мы не будем изобретать их сами.

## 8. Доступность и UX: минимум, который нельзя пропускать

Клиенты массажиста — разного возраста, многие с телефона. Это не «потом», а базовое качество.

1. **Кликабельное — это `<button>` или `<a>`, не `<div onClick>`.** Кнопка сама получает фокус по Tab, нажимается Enter/пробелом, скринридер называет её «кнопкой». В песочнице `<article onClick>` этого не умел.
   - `<a href>` — **переход** на другую страницу;
   - `<button>` — **действие** на этой странице.
2. **Не убирай обводку фокуса** (`outline-none`) без замены. Пользователь клавиатуры потеряется. Если стандартная обводка некрасивая, стилизуй её: `focus-visible:outline-2 focus-visible:outline-brand-700`.
3. **Контраст текста.** Светло-серый текст на белом не прочитать на солнце. Для основного текста бери оттенки `600–900`, для фона `50–100`. Firefox → Инспектор → вкладка **«Специальные возможности»** проверяет контраст.
4. **Тач-зоны ≥ 44×44px.** Палец не мышь. Кнопки и ссылки на телефоне: `min-h-11` (44px) или достаточный `py`.
5. **Шрифт не меньше 16px** (`text-base`) для основного текста. Иначе iOS приближает поля ввода при фокусе, а читать мелкое трудно.
6. **Смысл не только цветом.** «Красным — занятые слоты» не увидит дальтоник. Добавь текст или иконку.
7. **Картинкам `alt`.** Содержательной — описание, декоративной — `alt=""`.
8. **Анимации:** уважай `motion-reduce:` для тех, у кого в системе отключены анимации.

## 9. Как читать и писать длинный `className`

Порядок, в котором удобно и думать, и читать (плагин `prettier-plugin-tailwindcss` расставляет похожий порядок сам):

1. **раскладка:** `flex`, `grid`, `items-center`, `gap-4`
2. **размер:** `w-full`, `max-w-3xl`, `min-h-dvh`
3. **отступы:** `p-4`, `mx-auto`
4. **оформление:** `rounded-lg`, `border`, `bg-…`, `shadow-sm`
5. **текст:** `text-lg`, `font-semibold`, `text-stone-700`
6. **состояния и экраны:** `hover:…`, `focus-visible:…`, `md:…`

Пример, читаем слева направо: «флекс-колонка с промежутком 2, на всю ширину не больше 3xl, по центру, поля 4, скругление, рамка светло-серая, белый фон, на планшете — в ряд»:
```tsx
<section className="mx-auto flex w-full max-w-3xl flex-col gap-2 rounded-lg border border-stone-200 bg-white p-4 md:flex-row">
```

## 10. Отладка вёрстки: порядок действий

Когда «съехало» или «не работает», не меняй классы наугад. Иди по шагам:

1. **Найди элемент в Инспекторе** (правый клик → «Исследовать элемент»).
2. **Применились ли классы?** Справа в «Правилах» видно, какие стили действуют, а какие зачёркнуты (перебиты). Нет нужного правила вообще — смотри §6, «как Tailwind находит классы».
3. **Посмотри коробку** во вкладке «Разметка»: реальные размеры, margin, padding. Часто оказывается, что у родителя нет высоты или ширины.
4. **Включи подсветку Flex/Grid** значком рядом с элементом: видно, как на самом деле лежат дети.
5. **Временно подсвети границы**: добавь элементу и родителю `outline outline-red-500`. `outline`, в отличие от `border`, не меняет размеры.
6. **Правь в DevTools вживую**: в Инспекторе можно дописать класс или стиль и сразу увидеть эффект. Нашёл решение — перенеси в код.

## 11. Частые проблемы

| Симптом | Причина | Решение |
|---|---|---|
| Не центрируется по вертикали | у родителя нет высоты: он ровно с содержимое | `min-h-dvh` (или фиксированная высота) на родителе |
| `justify-center` двигает не туда | `flex-col` поменял оси местами | для вертикали в колонке `justify-*`, для горизонтали `items-*` |
| Класс в коде есть, стиля нет | имя класса собрано из кусков: `` `bg-${c}-500` `` | писать имена целиком (§6) |
| `mt-4` не действует | элемент `inline` (`span`, `a`) | `block` или `inline-block`, или отступ у родителя через `gap` |
| Длинный текст ломает флекс-ряд, вылезает | flex-ребёнок не сжимается меньше содержимого | `min-w-0` на ребёнке + `break-words` или `truncate` на тексте |
| На телефоне горизонтальная прокрутка | фиксированная ширина или картинка без ограничения | `max-w-full`, убрать `w-[…px]` |
| `h-screen` на телефоне обрезает низ | `100vh` не учитывает панель браузера | `min-h-dvh` |
| `z-50` не помогает | у элемента нет позиционирования | добавить `relative` |
| Рамка чёрная | Tailwind 4: `border` берёт цвет текста | `border border-stone-300` |
| Картинка растянута | пропорции не сохранены | `object-cover` + заданные `w`/`h` |
| У списка нет точек, у `h1` нет размера | Preflight сбросил стили браузера | задать явно: `list-disc pl-5`, `text-3xl font-bold` |

## 12. Практика

### Игры (обязательно, ~1 ч, на русском)
Лучший способ запомнить Flex и Grid — пройти две короткие игры. В обеих есть **русский язык** (переключатель языка в углу):
- **[Flexbox Froggy](https://flexboxfroggy.com/)** — 24 уровня, расставляешь лягушек по кувшинкам свойствами Flexbox.
- **[Grid Garden](https://cssgridgarden.com/)** — 28 уровней, поливаешь грядки свойствами Grid.

Игры учат названиям свойств CSS (`justify-content: center`). Переводи их в Tailwind по таблицам из §3: `justify-center`.

### Упражнения в `frontend/` (часть 4.5 задачи #6)
1. Стартовая страница из задачи: центр экрана, заголовок, подзаголовок, адаптивный размер.
2. Добавь под подзаголовком **кнопку** «Записаться» (пока без действия) со стилями: фон, скругление, `hover:`, `focus-visible:`. Проверь её с клавиатуры: Tab должен показать фокус.
3. Проверь страницу в режиме телефона (Ctrl+Shift+M, ширина 375px) и через Инспектор посмотри блочную модель заголовка и Flex-разметку `<main>`.

## 13. Шпаргалка Tailwind ↔ CSS

| Задача | Tailwind | CSS |
|---|---|---|
| в ряд / в столбик | `flex` / `flex flex-col` | `display: flex; flex-direction: column` |
| промежуток между детьми | `gap-4` | `gap: 1rem` |
| по центру (flex) | `items-center justify-center` | `align-items: center; justify-content: center` |
| раздвинуть по краям | `justify-between` | `justify-content: space-between` |
| сетка 3 колонки | `grid grid-cols-3` | `display: grid; grid-template-columns: repeat(3, minmax(0, 1fr))` |
| контейнер страницы | `mx-auto max-w-3xl px-4` | `margin: 0 auto; max-width: 48rem; padding: 0 1rem` |
| на весь экран по высоте | `min-h-dvh` | `min-height: 100dvh` |
| внутренний отступ | `p-4`, `px-4`, `py-2` | `padding: …` |
| скругление | `rounded-lg` | `border-radius: 0.5rem` |
| тень | `shadow-sm` | `box-shadow: …` |
| размер / жирность шрифта | `text-xl font-semibold` | `font-size: 1.25rem; font-weight: 600` |
| обрезать текст многоточием | `truncate` | `overflow: hidden; text-overflow: ellipsis; white-space: nowrap` |
| скрыть на телефоне | `hidden md:block` | `display: none` + медиа-запрос |
| только на телефоне | `md:hidden` | медиа-запрос `display: none` |

📖 Документация Tailwind (англ., но с примерами на каждый класс и поиском): [tailwindcss.com/docs](https://tailwindcss.com/docs).
