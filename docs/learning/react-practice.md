# Практика к задаче #5: прайс «Возрождения» шаг за шагом

> Пошаговое руководство к упражнению из `docs/sprints/sprint-01.md` (#5).
> Теория в `docs/learning/react-basics.md`. На каждом шаге указано, какой раздел конспекта нужен (§N).
> Готового решения здесь нет: есть план, инструменты, подсказки и способы проверить себя.
> Если застрял на 20+ минут, спроси меня, но сначала опиши, что пробовал.

**Что получится в итоге:** одна страница. Сверху кнопки фильтра «Все · 30 мин · 60 мин · 90 мин», под ними карточки услуг, внизу панель «Вы выбрали: …». Клик по карточке выбирает услугу, повторный клик снимает выбор.

## Шаг 0. Рабочее место (~30 мин)

### Инструменты и зачем каждый

| Инструмент | Зачем | Аналог в Rails-мире |
|---|---|---|
| **Терминал №1** | держит запущенный `npm run dev` (dev-сервер Vite) | `bin/rails server` |
| **Терминал №2** | git, проверка типов, установка пакетов | второй терминал для `rails c`, `git` |
| **VS Code** | редактор; TypeScript в нём встроен, ошибки типов подчёркиваются красным сразу | RubyMine / VS Code + ruby-lsp |
| **Firefox** | смотреть результат на `http://localhost:5173` | браузер на `localhost:3000` |
| **DevTools Firefox** (F12) | вкладка «Консоль» для ошибок и `console.log` | лог `log/development.log` |
| **React Developer Tools** (расширение) | видно дерево компонентов, их props и state, и подсветку перерисовок | `better_errors` + debug-панель, только для React |
| **git + GitHub** | коммит на каждый шаг, ревью по ссылке | как обычно |

### Что сделать

1. **Поставь React Developer Tools в Firefox.** Открой [addons.mozilla.org](https://addons.mozilla.org/ru/firefox/addon/react-devtools/) и нажми «Добавить в Firefox». После установки в DevTools (F12) появятся вкладки **⚛ Components** и **⚛ Profiler**. Если вкладок нет, перезагрузи страницу `localhost:5173`.
2. **Открой песочницу в VS Code:**
   ```bash
   cd ~/react-sandbox
   code .
   ```
3. **Запусти dev-сервер в терминале №1** (в VS Code: меню Terminal → New Terminal):
   ```bash
   npm run dev
   ```
   Этот терминал не трогай: он работает всё время, пока пишешь код. Сохранил файл, и страница в Firefox обновилась сама (это называется HMR, hot module replacement).
4. **Очисти шаблон.**
   - `src/App.tsx`: замени всё содержимое на минимальный компонент:
     ```tsx
     export default function App() {
       return <h1>Прайс кабинета «Возрождение»</h1>;
     }
     ```
   - `src/App.css`: удали всё содержимое (файл оставь, стили будешь писать сюда).
   - `src/index.css`: тоже очисти, чтобы стили шаблона не мешали.
   - Если в `App.tsx` был `import './App.css'`, верни его первой строкой.
   - В Firefox должен остаться только заголовок.
5. **Git и GitHub (терминал №2).** `create-vite` не создаёт git-репозиторий, поэтому:
   ```bash
   git init
   git add .
   git commit -m "chore: init Vite React TS sandbox"
   ```
   Затем создай пустой репозиторий `react-sandbox` на GitHub (через сайт, кнопка «New repository», **без** README и .gitignore) и выполни команды, которые GitHub покажет в блоке «…or push an existing repository». Если стоит `gh`, всё делается одной командой:
   ```bash
   gh repo create react-sandbox --public --source=. --push
   ```

### Как писать код в этой задаче
Пиши руками. Claude Code в VS Code можно спрашивать «что значит эта ошибка» или «почему так», но не «напиши компонент»: цель задачи — чтобы руки и голова запомнили.

✅ **Проверка:** в Firefox только заголовок, в F12 → ⚛ Components виден компонент `App`, репозиторий на GitHub с первым коммитом.

## Шаг 1. Данные и типы (~30 мин) — §2

**Цель:** описать, как выглядит услуга, и завести список услуг. Пока без интерфейса.

**Инструмент:** VS Code. Ошибки типов он подчёркивает сразу, в терминале ничего запускать не нужно.

### Что сделать
1. Создай папку и файл `src/data/services.ts`. Расширение `.ts`, а не `.tsx`: здесь нет JSX, только данные.
2. Опиши тип и экспортируй его:
   ```ts
   export type Service = {
     // id — число
     // title — строка
     // durationMinutes — число
     // priceRub — число (цена в рублях, целое)
     // description — НЕобязательная строка (вспомни знак из §2)
   };
   ```
   Заполни поля сам по комментариям.
3. Ниже экспортируй массив `services` с типом `Service[]` из 6–8 услуг. Нужны длительности **30, 60 и 90** минут, хотя бы по одной каждой. Примерный набор: классический массаж, массаж спины, шейно-воротниковая зона, антицеллюлитный, массаж лица, общий массаж. Цены придумай или спроси у мастера. У 2–3 услуг сделай `description`, у остальных не указывай его вовсе.
4. Импортируй массив в `App.tsx` и выведи в консоль, чтобы убедиться, что всё связалось:
   ```tsx
   import { services } from "./data/services";
   console.log(services);
   ```

- Проверка типов из терминала (то же самое, что делает CI):

## Шаг 2. Статичный список (~1 ч) — §3, §4, §5

**Цель:** показать услуги карточками. **Ни одного `useState`** на этом шаге: только props.

**Инструменты:** VS Code, Firefox, ⚛ Components (смотреть props).

### Что сделать
1. Создай папку `src/components/`.
2. **`ServiceCard.tsx`** — одна карточка.
   - Опиши тип пропсов `ServiceCardProps`. Подумай: передавать каждое поле отдельно (`title`, `price`…) или всю услугу целиком (`service: Service`)? Оба варианта рабочие, второй короче. Выбери и запомни, почему.
   - Внутри покажи название, длительность («60 мин»), цену («2 500 ₽») и описание, **только если оно есть** (§5, условный рендер).
   - Корневой элемент дай `className="service-card"`, чтобы потом стилизовать.
3. **Форматирование цены.** Сделай маленькую функцию-помощник, например в `src/utils/format.ts`:
   ```ts
   const rub = new Intl.NumberFormat("ru-RU");
   export function formatPrice(value: number): string {
     return `${rub.format(value)} ₽`;
   }
   ```
   `Intl.NumberFormat` встроен в браузер, он ставит пробел между разрядами по русским правилам. Аналог в Rails — `number_to_currency`. Это обычная функция, не компонент: она возвращает строку, а не JSX.
4. **`ServiceList.tsx`** — список. Получает `services: Service[]` через props и рендерит `ServiceCard` для каждого элемента через `map`. Не забудь `key` (§5: что взять в качестве ключа и почему не `index`).
5. **`App.tsx`**: импортирует `services` и рендерит `<ServiceList services={services} />`. Убери `console.log` из шага 1.
6. **Немного CSS** в `App.css`, чтобы было на что смотреть: карточки в сетку (`display: grid; grid-template-columns: repeat(auto-fill, minmax(220px, 1fr)); gap: 16px;`), рамка, отступы. Красота не оценивается, нужно, чтобы на шаге 4 было видно подсветку.

### Подсказки
- Компонент экспортируй через `export function ServiceCard(...)` и импортируй как `import { ServiceCard } from "./ServiceCard"`. Так проще искать по проекту, чем с `export default`.
- Если в консоли видишь `Each child in a list should have a unique "key" prop`, значит, `key` не на том элементе. Он ставится на **внешний** элемент внутри `map`, то есть на `<ServiceCard key=... />`.

### Проверь себя в ⚛ Components
Открой F12 → ⚛ Components и кликни на любой `ServiceCard`. Справа видны его **props**. Ты видишь те же данные, что передал из `ServiceList`. Секции «hooks»/state нет: у компонента нет состояния, и это правильно.

✅ **Проверка:** все услуги на экране, цены вида «2 500 ₽», описания только там, где они есть, в консоли нет предупреждений, `npx tsc -b` молчит.
**Коммит:** `feat: render static services list`

## Шаг 3. Фильтр по длительности (~1–1,5 ч) — §6, §7, §10

**Цель:** кнопки «Все · 30 · 60 · 90» показывают только услуги выбранной длительности.

**Инструменты:** VS Code, ⚛ Components (смотреть state), консоль.

### Сначала подумай (5 минут, без кода). Это шаги 3–4 из «Мыслим как React» (§10)
1. **Какой минимальный state нужен?** Подсказка: список услуг не меняется, это не state. Отфильтрованный список вычисляется, это тоже не state. Что тогда остаётся?
2. **Какой у него тип?** Значение «Все» нужно как-то представить. Варианты:
   - `number | null`, где `null` значит «все»;
   - union из литералов: `type DurationFilterValue = "all" | 30 | 60 | 90;`.
   Второй строже: TS не даст случайно поставить 45. Выбери сам.
3. **Где живёт этот state?** Кому он нужен: кнопкам (подсветить активную) и списку (отфильтровать). Значит, он живёт в их общем родителе. В каком?

### Что сделать
1. **State в `App`** (если ты пришёл к тому же выводу):
   ```tsx
   const [duration, setDuration] = useState<DurationFilterValue>("all");
   ```
2. **Вычисли отфильтрованный список прямо в теле `App`**, обычным `filter` перед `return` (§10, «храни минимум, остальное вычисляй»). В `ServiceList` передавай уже отфильтрованный массив. Сам `ServiceList` менять не нужно, и это хороший знак.
3. **`DurationFilter.tsx`** — компонент без собственного state. Получает через props:
   - `value` — текущее значение фильтра (чтобы подсветить активную кнопку);
   - `onChange` — функцию, которую вызывает при клике с новым значением.

   Типизация колбэка с аргументом:
   ```ts
   onChange: (value: DurationFilterValue) => void;
   ```
   Кнопки не пиши четыре раза руками: заведи массив вариантов и сделай `map`:
   ```ts
   const options: { value: DurationFilterValue; label: string }[] = [
     { value: "all", label: "Все" },
     // ...
   ];
   ```
   Активную кнопку отметь классом, например `className={... ? "filter-btn active" : "filter-btn"}`.
   Помни про `onClick={() => onChange(option.value)}`, а не `onClick={onChange(option.value)}` (§6).
4. **Пустое состояние.** Если после фильтра массив пустой, покажи «Нет услуг такой длительности». Проверить можно, временно убрав из данных все 90-минутные услуги. Где разместить проверку: в `App` или в `ServiceList`? Подумай, какой компонент «знает», что список пуст.

### Проверь себя в ⚛ Components
Кликни на `App`. В разделе **hooks** видно `State: "all"`. Нажимай кнопки фильтра, и значение меняется на глазах. Это и есть «UI = f(state)»: ты меняешь только одно значение, а остальное React перерисовывает сам.

### Эксперимент к вопросу «что вызывает рендер» (5 минут)
Временно добавь в начало каждого компонента строку `console.log("render", "ServiceCard")` (с его именем). Нажми фильтр и посмотри в консоль:
- кто перерисовался, когда изменился state в `App`?
- перерисовался ли `DurationFilter`, хотя его state не менялся (его у него нет)?

Логи выводятся дважды? Это `StrictMode` (§9), не баг. Запиши наблюдение для README и убери логи.

Ещё нагляднее: ⚛ Components → шестерёнка ⚙ → включи **«Highlight updates when components render»**. Перерисованные компоненты будут вспыхивать рамкой.

✅ **Проверка:** фильтр работает, активная кнопка выделена, пустое состояние показывается, `npx tsc -b` молчит.
**Коммит:** `feat: add duration filter`

## Шаг 4. Выбор услуги и итоговая панель (~1–1,5 ч) — §6, §7, §10

**Цель:** клик по карточке выбирает её (подсветка), повторный клик снимает выбор, внизу панель с выбранной услугой и кнопкой «Сбросить».

### Сначала подумай
1. **Какой state?** Вспомни §10: хранить объект услуги или её `id`? Какой тип, если ничего не выбрано?
2. **Где он живёт?** Он нужен карточкам (подсветка) и `Summary` (текст). Их общий родитель?
3. **Как данные пойдут вниз и события вверх?** Нарисуй на бумаге дерево компонентов со стрелками, как в §10. Этот рисунок потом пойдёт в README.

### Что сделать
1. **State выбора в `App`.**
2. **Найди выбранную услугу** по id перед `return` (`find`). Это вычисляемое значение, не state.
3. **Протяни данные до карточки.** `ServiceList` получает два новых пропса: `selectedId` и `onSelect`. Он отдаёт каждой карточке:
   - `isSelected: boolean` — вычисленное сравнение id;
   - колбэк на клик.
   `ServiceList` сам ничего не решает, он только передаёт. Такой компонент называют «прокладкой», и это нормально.
4. **Повторный клик снимает выбор.** Подумай, что должно оказаться в state, если кликнули по уже выбранной карточке. Логику «выбрать или снять» удобно держать в одном обработчике в `App` (`handleSelect`), а не размазывать по карточкам.
5. **Подсветка в `ServiceCard`:** класс `service-card selected` при `isSelected` и CSS для `.selected` (другая рамка или фон). Добавь `cursor: pointer`, чтобы было понятно, что карточка кликабельна.
   💡 Для доступности кликабельную карточку лучше делать `<button>` (или вложить кнопку внутрь). Тогда она работает и с клавиатуры (Tab, Enter). Попробуй.
6. **`Summary.tsx`** — получает выбранную услугу (`Service | undefined`) и колбэк сброса.
   - Ничего не выбрано: «Выберите услугу».
   - Выбрано: «Вы выбрали: Классический массаж, 60 мин, 2 500 ₽» и кнопка «Сбросить».
   - Используй тот же `formatPrice`.
7. **Решение для README.** Выбери услугу 90 мин, потом включи фильтр «30 мин». Карточка скрылась, а панель? Реши, как должно быть:
   - **оставить выбор** — пользователь просто смотрит другие услуги, но уже определился;
   - **сбросить выбор** — на экране не должно быть выбранного, но невидимого.

   Реализуй выбранный вариант и в 2–3 предложениях объясни в README, почему. Подсказка для варианта «сбросить»: это можно сделать прямо в обработчике смены фильтра, **без `useEffect`**.

### Проверь себя в ⚛ Components
- У `App` теперь два state. Кликай по карточкам и смотри, как меняется второй.
- У `ServiceCard` в props видно `isSelected: true/false`. Состояния у карточки нет: она «глупая», и это правильно.

✅ **Проверка:** выбор, снятие выбора, сброс кнопкой, поведение при фильтре соответствует решению, в консоли чисто, `npx tsc -b` молчит.
**Коммит:** `feat: select service and show summary`

## Шаг 4½. Эксперимент «почему нельзя мутировать state» (~15 мин) — §8

Этот шаг нужен, чтобы ответить на вопрос 2 из личного опыта, а не пересказом. **Не коммить его.**

1. Временно положи список услуг в state `App`: `const [items, setItems] = useState(services);`, а фильтр сделай по `items`.
2. Добавь кнопку «Поднять цены на 10%» и сделай обработчик **неправильно**:
   ```tsx
   items.forEach((s) => { s.priceRub = Math.round(s.priceRub * 1.1); });
   setItems(items);
   ```
   Нажми. Цены на экране не изменились. А если после этого кликнуть фильтр? Почему тогда изменились?
3. Сделай **правильно**, через `map` и `{ ...s, priceRub: ... }` (таблица в §8). Нажми, и всё обновилось сразу.
4. Запиши в README своими словами, что произошло. Откати эксперимент: `git checkout -- src/`.

## Если что-то пошло не так

| Симптом | Где смотреть | Частая причина |
|---|---|---|
| Белый экран | Консоль Firefox (F12) | ошибка в JSX или импорте, читай первую красную строку |
| Красное подчёркивание в VS Code | наведи мышку | несовпадение типов; сообщение TS обычно точно говорит, что ожидалось |
| Клик ничего не меняет | ⚛ Components: меняется ли state? | `onClick={fn()}` вместо `onClick={fn}`, мутация state, колбэк не передан вниз |
| Страница не обновляется после сохранения | терминал №1 | dev-сервер упал: смотри ошибку, перезапусти `npm run dev` |
| `Cannot find module './...'` | путь в импорте | регистр букв в имени файла, лишнее или пропущенное расширение |
| Предупреждение про `key` | консоль | `key` не на внешнем элементе внутри `map` |
